# 교차 검증 — 다른 PC 에서도 같은 출력이 나오는가

GeulPU 는 계산을 정확한 정수 계약으로 해서, 같은 입력이면 어디서 어떻게 계산해도 같은 비트를 낸다고 주장한다. 이 폴더는 그 주장을
**다른 PC** 에서 확인하는 스크립트다.

## 실행
git 이 있는 윈도 PC 에서:
```
git clone https://github.com/wwoosshh/GeulPU
GeulPU\교차검증\run.bat
```
`run.bat` 이 차례로 한다.
1. 환경 검사 — 운영체제(판 · 빌드), 모든 GPU 의 이름 · 연산 능력 · VRAM · 드라이버와 그 방식 · VBIOS · PCIe · 최대 클럭 · 전력 한도,
   nvcuda.dll 판 · CUDA 판, CPU · RAM, 디스크, 하드웨어 가속 GPU 일정, 전원 계획, git, GeulPU 커밋. 실패가 있으면 여기서 멈춘다.
2. 소스에서 빌드(1~3 분) — 글 1.3.1 공개 배포판의 컴파일러로 글 저장소의 고정 커밋(`시험/글저장소커밋.txt`, CI 와 같다)의 글 컴파일러를
   두 번 빌드하고(고정점), PTX 뒷단 → 서버 → 커널 생성기 → 7B Q8_0 모듈 → PTX. 단계마다 기준 PC 에서 만든 것과 SHA-256 을 대조한다.
3. 모델 받기 — DeepSeek-R1-Distill-Qwen-7B Q8_0 (8.1 GB, Hugging Face `unsloth/DeepSeek-R1-Distill-Qwen-7B-GGUF`).
   `교차검증\` 에 미리 넣어 두면 받지 않는다.
4. 생성 — 서버를 127.0.0.1 에서만 띄우고, 수학 문제 32 개를 탐욕 생성(temperature 0, 상한 3200 토큰)으로. 걸음마다의 로짓 해시도 받는다.
5. 비교 — 기준 PC 의 출력(`expected.json`)과 글자 하나까지.
6. `교차검증\result-….zip` — 환경 · 빌드 해시 · 출력 · 비교 · 기록. 사용자 이름 · 컴퓨터 이름 · GPU 고유번호는 넣지 않고 경로는 지운다.

필요: 윈도 10/11 64 비트, git, NVIDIA RTX 30 시리즈 이상(VRAM 12 GB 이상 권장 — 10 GB 는 슬롯을 줄여 느리게), 디스크 여유 10 GB.
파이썬은 필요 없다(글 1.3.1 로 컴파일러를 빌드하지 못할 때만 대신 쓴다).

## 실험
- 문제: 정답을 코드로 계산한 수학 문제 32 개(`requests.json` — 씨앗 31 로 만든 합성 문제, 표준 벤치마크가 아니다). 프롬프트는 모든 PC 에
  같은 토큰열(BOS + llama-server 의 대화 틀).
- 서버: `호스트/서버.gl` 에 [`토크나이저_R1.diff`](토크나이저_R1.diff) 만 더해 빌드한다(스크립트가 `work\src` 의 사본에 적용). 이 모델의
  `tokenizer.ggml.pre`(`deepseek-r1-qwen` — 바이트 BPE 의 앞자르기는 qwen2 와 같다)를 받고 끝 토큰을 `<｜end▁of▁sentence｜>` 로 둔다.
  계산(커널)은 그대로다.
- 판정(실행 전에 적음): 출력 글이 32 문제 모두 기준과 같으면 통과. 하나라도 다르면 그 GPU · 드라이버와 처음 갈린 자리를 그대로 기록한다.
  빌드 해시가 기준과 다르면 그것도 함께 기록한다(출력이 다를 때 빌드 탓인지 GPU 탓인지 가르기 위해).
