# 공식 실행 스크립트

단계마다 판정의 값을 낸 스크립트를 돌린 그대로 둔다(22 ~ 27단계). 고정한 커밋에서 빌드부터 시험 · 재기까지 하고, 결과를 `문서/결과/<단계>/` 에,
큰 파일(로짓 등)은 작업 폴더에 둔다. GPU 가 들지 않는 몫 — 글 컴파일러 · PTX 뒷단 · 생성기 · 호스트의 빌드, 모듈(소스 · PTX · SASS)의 바이트와
레지스터 넘침, 계약의 CPU 참조 자체 시험, 판 표 — 은 커밋마다의 빠른 점검(CI — [README](../README.md) 의 점검 절)이 본다. 공식 실행은 GPU 가
드는 것(판 · 다섯 길 · 끝에서 끝의 비트 대조와 속도)에 맞춘다. 재현하려면:

```
bash 공식실행/공식25.sh <저장소의 절대 경로> <작업 폴더>
```

- 준비물: [README](../README.md) 의 빠른 시작(글 컴파일러 · 글 PTX 뒷단을 `../geul-lang-v2` 에), 모델 파일(`모델/` — 단계 문서에 받는 곳과 만드는
  명령), llama.cpp 견주기가 있는 단계는 그 단계가 쓴 Windows CUDA 공식 배포본을 `도구/llama-b<번호>/` 에(29단계까지 b11496, 30단계부터 그때의
  최신 — 30단계는 b11567), Python 3.12 + numpy.
- `$W/입력18d.py` · `$W/공식2x채팅.ps1` 처럼 작업 폴더에서 부르는 도우미는 이 폴더에 있다 — 돌리기 전에 작업 폴더로 복사한다.
- 모든 값은 RTX 4070 Ti(12 GB) 한 장 · Windows 11 에서 잰 것이다. 다른 GPU 에서 돌린 값은 아직 없다 — 비트 판정(CPU 참조 · 길끼리 대조)은
  GPU 와 상관없이 같아야 하고, 속도의 비는 GPU 마다 다를 수 있다.
