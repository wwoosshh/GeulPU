## 차례 — DOI 를 먼저 받는다

Zenodo 는 한 번 Publish 하면 파일을 바꿀 수 없다(새 판을 내야 한다). README 와 논문 부록 C 에 DOI 가 들어가야 하므로 차례가 중요하다.

1. https://zenodo.org 에 로그인(GitHub 계정으로 가능) → **New upload**.
2. 파일을 올리기 전에 **Digital Object Identifier** 칸에서 **No, I need one** 을 고르고 **Get a DOI now!** 를 누른다 →
   `10.5281/zenodo.XXXXXXX` 가 예약된다. 이 번호를 README(이 폴더와 올릴 판 둘 다)와 논문 부록 C · 참고문헌 · PDF 에 넣어 커밋한다.
   — **예약함(2026-10-16): `10.5281/zenodo.23417759`**, 모두 넣었다.
3. DOI 가 들어간 `README.md` 를 받아(저장소에서 내려받기) 위 파일들과 함께 올린다.
4. 아래 메타데이터를 채운다.
5. **Publish**. 되돌릴 수 없다 — 누르기 전에 파일 목록과 DOI 가 README 의 것과 같은지 본다.

## 메타데이터 (그대로 붙여 넣기)

- **Resource type**: Dataset
- **Title**: `Raw data — GeulPU stage 40: engine numerical loss and LLM failure symptoms`
- **Creators**: `Woo, Sunghyeun` — Affiliation `Chungwoon University` (ORCID 가 있으면 함께)
- **Description**:

  > Every token generated and every per-step probability measured in the pre-registered experiment of the paper *Engine Numerical
  > Loss Re-Rolls but Does Not Degrade: An Exact-Baseline Study of LLM Failure Symptoms* (Sunghyeun Woo, 2026). Three inference
  > engines — GeulPU under its written precision contract (exact baseline), llama.cpp b11669, and GeulPU with one added loss — were
  > given identical token inputs and decoded greedily: Qwen2.5-7B-Instruct (Q8_0) on 1,296 Korean prompts (Language Confusion
  > Benchmark, long-form writing, three symptom triggers) and DeepSeek-R1-Distill-Qwen-7B (Q8_0) on 600 gsm8k problems. The record
  > holds the generated tokens with top-20 log-probabilities per step for all arms, llama.cpp's per-step distributions at the
  > baseline's prefixes, the fragile steps (near-ties between a normal and an abnormal token), forced-token continuations,
  > two-turn contamination dialogs, determinism re-runs, the exact token ids sent, and the engine executables and kernels used.
  > With the GeulPU repository (commit 0a5ab97) and the two public GGUF model files, every number in the paper can be recomputed;
  > every case generated by the baseline can be replayed bit for bit. README.md describes the files and formats; MANIFEST.sha256
  > lists the SHA-256 of every file.
