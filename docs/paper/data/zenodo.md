## 차례 — DOI 를 먼저 받는다

Zenodo 는 한 번 Publish 하면 파일을 바꿀 수 없다(새 판을 내야 한다). README 와 논문 부록 C 에 DOI 가 들어가야 하므로 차례가 중요하다.

1. https://zenodo.org 에 로그인(GitHub 계정으로 가능) → **New upload**.
2. 파일을 올리기 전에 **Digital Object Identifier** 칸에서 **No, I need one** 을 고르고 **Get a DOI now!** 를 누른다 →
   `10.5281/zenodo.XXXXXXX` 가 예약된다. 이 번호를 README(이 폴더와 올릴 판 둘 다)와 논문 부록 C · 참고문헌 · PDF 에 넣어 커밋한다.
   — **예약함(2026-10-16): `10.5281/zenodo.23417759`**, 모두 넣었다.
3. DOI 가 들어간 `README.md` 를 받아(저장소에서 내려받기) 위 파일들과 함께 올린다.
4. 아래 메타데이터를 채운다.
5. **Publish**. 되돌릴 수 없다 — 누르기 전에 파일 목록과 DOI 가 README 의 것과 같은지 본다.

## 브라우저 업로드가 끊기면 — 명령줄로 올리기

작은 파일은 올라가는데 큰 zip 이 몇 % 에서 빨갛게 멈추면 연결이 중간에 끊긴 것이다(Zenodo 는 끊긴 업로드를 이어 받지 못한다 —
휴지통으로 지우고 다시 올려야 한다). 브라우저를 바꾸거나(확장 기능 끄기, 시크릿 창), VPN · 원격 세션을 끊고, 한 번에 파일 하나씩
올려 본다. 그래도 안 되면 API 로 올린다:

1. zenodo.org → 계정 → **Applications** → **Personal access tokens** → New token, 범위 `deposit:write`. 토큰은 아무에게도 보내지 않는다.
2. 이 PC 의 Git Bash 나 WSL 에서:

   ```
   ZENODO_TOKEN=<토큰> bash 공식실행/zenodo-올리기.sh 23417759 F:/geulpu-work/s40-zenodo
   ```

   파일 8 개를 차례로 올리고(이미 같은 것이 있으면 건너뛰고, 끊기면 8 번까지 다시), 끝에 Zenodo 쪽 파일 목록과 md5 를 찍는다. 특정
   파일만 올리려면 뒤에 이름을 적는다.
3. 큰 zip 이 그래도 자꾸 끊기면(502) **조각으로** 올린다 — 24 MB 조각(`parts/<이름>.partNN`)과 이어 붙이는 법 · 조각 해시를 적은
   `PARTS.txt` 가 함께 올라간다(README 에도 이어 붙이는 법이 있다):

   ```
   PARTS=24m bash 공식실행/zenodo-올리기.sh 23417759 F:/geulpu-work/s40-zenodo
   ```

   이때 Zenodo 에는 통째 zip 대신 조각이 올라가므로, 먼저 올리다 만 통째 zip 이 있으면 화면에서 지운다. 파일 수는 5 + 조각 약 70 + 1 로
   Zenodo 의 기록당 100 개 한도 안이다.
