# 16단계 — 자체 컴파일러 PTX 탐침: 글 컴파일러가 GPU 코드를 내는가 (2026-10-10)

사용자 결정(같은 날, 15단계 뒤): 1~15단계의 PTX 는 모두 파이썬(글 참조 구현의 앞단 사본 + `컴파일러/글ptx.py`)이 냈다. 글의 자체 호스팅
컴파일러(geul-lang-v2 `self/*.gl`)에는 PTX 뒷단이 없다. 연구 문서(docs/17 §8)의 운영 규칙 — "참조 구현에서 먼저 시험하고, 이정표를 닫을 때
자체 컴파일러로 옮겨 고정점과 바이트 대조를 되찾는다" — 의 뒷부분을 한 번도 하지 않았다. 그래서 15단계까지의 비트 · 속도는 파이썬 컴파일러의
결과다.

이 단계는 옮기기가 되는지를 잰다. **실패하면 글 길을 폐기한다**(파이썬 엔진으로 가거나 여기서 접는다 — 사용자). 판정 기준을 결과보다 먼저 적는다.

## 판정 전에 확인한 것

- 자체 컴파일러의 앞단(렉서 · 파서 · 의미 · 하강)은 GPU 커널 소스에서 참조 구현과 **바이트까지 같은 IR** 을 낸다 — 탐침 커널 셋(벡터덧셈 ·
  곱더하기 · 제곱차)과 GeulPU 의 손으로 쓴 `커널/gpt2.gl`(IR 11,740 줄). 둘 다 `시작하기` 가 없는 소스는 거부해서, 빈 `시작하기` 를 붙여 덤프했다.
- 15단계의 Qwen2 모듈(글 소스 107,416 줄)은 자체 컴파일러가 읽지 못한다 — 연구 옵션 `반실수` 타입이 참조 구현에만 있다.
- 탐침의 실행 길은 이미 글이다: `research/gpu/탐침/실행기.gl` · `곱더하기실행기.gl`(글로 쓴 호스트가 `쿠다.gl` 로 드라이버를 부른다). 파이썬은
  PTX 를 내는 `글ptx.py` 하나뿐이다.

## 할 것

자체 컴파일러에 **글로 쓴 PTX 뒷단**을 넣는다 — 자체 앞단이 만든 IR 을 `글ptx.py` 와 같은 규칙으로 PTX 텍스트로 옮긴다(이름 바꾸기, 반올림을
적기, 지역 변수의 레지스터, 주소 공간, 오류 칸 등 그 소스가 쓰는 만큼). 자체 컴파일러의 본 실행 파일 · 고정점은 건드리지 않고, `IR덤프.gl` 처럼
따로 빌드하는 도구로 둔다.

## 판정 (미리 정함)

| 판정 | 기준 (미리 정함) | 상태 |
|---|---|---|
| 16a 같은 PTX | 1단계 탐침 커널 넷(`벡터덧셈` · `벡터덧셈_보폭` · `곱더하기` · `제곱차`)의 PTX 가 GeulPU `컴파일러/글ptx.py`(지금의 판)가 낸 PTX 와 바이트까지 같다 | **통과** — 넷 모두 바이트까지 같다(2,210 · 2,611 · 2,597 · 2,772 B). 글 뒷단을 처음 돌린 결과다 |
| 16b 돈다 | 그 PTX 를 글로 쓴 실행기(`실행기.gl` · `곱더하기실행기.gl`)가 GPU 에서 돌려 틀린 값 0 — 1단계와 같은 확인 | **통과** — 벡터덧셈 · 벡터덧셈_보폭(블록 16) 1,048,576 개 중 틀린 값 0(합[12345] = 37035), 곱더하기는 CPU 의 글과 비트가 다른 값 0(한 번 반올림과 다른 값 245,734 — 1단계와 같은 수), 제곱차는 다른 값 0 · +0 이 아닌 값 0. 실행기도 자체 컴파일러로 빌드한 글 프로그램이다(제곱차는 1단계의 파이썬 재기 대신 글 실행기를 새로 썼다 — 밝혀 둘 것 1) |

판정이 아닌 기록: 들인 시간 · 글 뒷단의 줄 수, 그리고 같은 뒷단이 GeulPU 의 `커널/gpt2.gl`(공유 메모리 · 동기화 · 원자 · 셔플 등을 쓰는 손 커널)에서
어디까지 같은 PTX 를 내는지.

## 결과 (2026-10-10)

**두 판정 모두 통과 — 글 길을 폐기하지 않는다.** 1단계 탐침 커널 넷은 이제 파이썬 없이 글 소스에서 GPU 실행까지 간다:

    글 소스 ─(자체 앞단 + 글 PTX 뒷단, 둘 다 자체 컴파일러가 빌드)→ PTX ─(글 실행기, 자체 컴파일러가 빌드)→ nvcuda.dll → GPU

### 만든 것 (geul-lang-v2, 가지 research/gpu)

- `research/gpu/자체PTX/PTX.gl` (글 1,122 줄) — 자체 앞단(`self/하강.gl` 을 포함 — 렉서 · 파서 · 의미 · 하강 · 인라인)의 IR 을 `글ptx.py` 와 같은
  규칙으로 PTX 로. 옮긴 규칙: 이름 바꾸기, 모듈 · 커널 머리, 실행한도 · 상수나눗셈 주석, 지역 변수의 레지스터(2a), 주소 공간(2a), a[x + c] 의
  상수 접기(3단계 — 접힌 것이 있으면 아직 거부), 명령 모두(반올림을 적은 부동소수 — PTX 계약 P1), 범위 검사(2c), 내장 대부분.
  아직 옮기지 않은 규칙이 닿는 커널은 다른 PTX 를 내지 않고 오류로 멈춘다.
- `self/의미.gl` 에 조각모드(5 줄) — `시작하기` 없이 함수들만. 참조 구현 `sema.analyze(fragment=True)` 와 같은 규칙.
- `research/gpu/탐침/제곱차실행기.gl` (91 줄) — 제곱차 커널을 GPU 에서 돌려 CPU 의 글과 비트로 맞춘다.
- 도구 셋(PTX 뒷단 · 실행기 셋) 모두 자체 호스팅 컴파일러(`geulc 1.2.1` 자체 판)로 빌드했다.

### 판정이 아닌 기록

- **들인 것**: 판정을 적은 커밋(21:13)에서 두 판정 통과(21:27)까지 14 분, 글 1,213 줄. 글 뒷단은 처음 돌린 PTX 가 넷 모두 바이트까지 같았다.
- **자체 컴파일러는 그대로다**: 조각모드를 넣은 뒤 `build.py selfhost` — 구문 · IR 덤프 163 개 · 부정 시험 66 개 · exe 바이트 140 개 불일치 0,
  고정점(1 · 2 · 3세대 바이트 같음). 그 컴파일러로 도구를 다시 빌드해도 16a · 16b 결과가 같다. 커밋: geul-lang-v2 `research/gpu` 262e7b1.
- **GeulPU 의 `커널/gpt2.gl`**(손 커널 넷): 첫 나눗셈(`sdiv`)에서 멈춘다 — 2e 의 정수 범위 증명(32 비트로 좁히기)을 아직 옮기지 않았다.
- **남은 규칙**(`글ptx.py` 에서 옮길 것): 2e 의 정수 범위 증명(구간 해석 — 파이썬의 큰 정수 계산을 64 비트 글로 옮기려면 넘침을 다뤄야
  한다), 상수 나눗셈(12단계), 끝 0 비트 증명 · 네 칸 묶어 읽기 · 쓰기(3단계), 바이트 마당 변환(5단계), 정수텐서곱 · 행렬조각읽기 ·
  비동기 복사 · 비동기 장벽 · 미리읽기, 반실수(앞단부터). 그다음이 호스트(GGUF · 토크나이저 · 엔진)와 커널 생성기를 글로.

### 밝혀 둘 것

1. **제곱차의 실행기.** 1단계에서 제곱차는 파이썬 재기(`제곱차재기.py`)로 돌렸다. 16b 를 글로만 확인하려고 글 실행기를 새로 썼다 — 같은 입력을
   첫째 · 둘째에 넘기고, CPU 의 글(곱해서 반올림, 빼서 반올림)과 비트로 맞춘다.
2. **정답지는 파이썬판이다.** 16a 는 `글ptx.py`(지금의 GeulPU 판)가 낸 PTX 와 견줬다. 글 뒷단이 그 규칙을 옮긴 것이라, 파이썬판의 결과(1~15단계)가
   글 컴파일러의 결과가 되려면 그 커널들의 PTX 가 바이트까지 같아야 한다 — 이 단계는 탐침 넷까지만 그렇다.
