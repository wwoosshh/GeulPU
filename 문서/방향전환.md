# 방향 전환 — 엔진에서 측정 도구로 (2026-10-16)

*40단계의 사전 등록([40단계.md](40단계.md) '방향 전환')을 옮겨 적은 것이다.*

## 왜 바꾸나

2026-10-13 에 사용자가 정한 생존 기준은 둘이었다 — (1) 같은 최적화에서 계약의 값(정확함을 지키는 데 드는 셈)이 1.01 안팎이어야 하고,
(2) 이득이 사용자 눈에 보이고 남이 이미 주지 않는 것이어야 한다. 2026-10-16 에 다시 조사하니 GeulPU 만 준다고 여긴 능력의 대부분을 남이 더
싸게 풀고 있었다.

| GeulPU 가 내세운 능력 | 바깥 |
|---|---|
| 묶음 · 동시 요청 · 캐시와 상관없이 같은 비트 | vLLM · SGLang 의 결정 모드(2025), Vosti(arXiv 2609.38981 — 형식 검증) |
| NVIDIA 세대가 달라도 같은 비트 | 2609.25624(Ampere · Ada · Hopper — 선형층, 더 빠름), Gensyn REE |
| GPU 결과를 CPU 에서 비트까지 다시 내기 | 2606.00279(엔진을 고치지 않고 CPU 에뮬레이터로 — 속도 값 없음) |
| NVIDIA · Apple · CPU 의 같은 바이트 | Gensyn REE(핵심은 비공개 바이너리) |

남은 것은 AMD 를 포함한 회사 사이의 같은 비트 · 공개된 계약 · GGUF 의 조합이다. 이 자리를 지키려면 줄어드는 섬에서 자본이 있는 팀들과
경주해야 하고, 그 팀들은 사용자가 엔진을 바꾸지 않아도 되게 푼다.

## 무엇을 내려놓고 무엇을 두나

- **내려놓는 것**(사용자 결정 2026-10-16): 생존 기준 둘. 둘 다 엔진을 제품으로 견줄 때의 기준이다.
- **새 기준**: 단계마다 미리 적은 연구 질문 하나에 답했는가. GeulPU 는 그 답을 얻는 측정 도구다 — 손실이 적힌 대로만인 기준(fp64 에
  가까움), 엔진 잡음 0, 적은 대로만 넣는 손실, 어느 기계에서나 다시 열리는 사례(캡슐).
- **첫 질문**(40단계): 계산 손실이 LLM 의 실패 증상(반복 · 엉뚱한 언어 · 깨진 맞춤법 · 끝내지 못함 · 틀린 답)을 만드는가 — 주사위를
  다시 굴리는가(흔들림), 비정상 쪽으로 기울이는가(망가짐). 지금까지 GeulPU 는 손실을 재고 재현했지만 "그 손실이 무엇을 망치는가"에는 답하지
  못했다. 이것이 사용자의 연구(AI 계산의 의미 손실 — 값의 자리 · 정체를 잃는 손실이 익숙한 증상으로 나타난다)의 시험이기도 하다.
- **멈추는 것**: 새 모델 계열 · 앱의 새 기능 · 속도 단계 · 정기 릴리스. 39단계가 마지막 넓히기 단계다(그 릴리스는 사용자가 정한다).
- **이어 가는 것**: CI · 교차검증, 연구 패널(사례를 들여다보는 화면), 캡슐(사례 하나의 단위).
- **글(geul) 언어**: GPU 일(커널 · 서버 · 앞으로의 손실 주입기)은 계속 글로 쓴다. 문법의 이득(docs/17 의 주장 B · C)은 생존 조건이 아니라
  따로 미리 등록하는 질문이다.

## 결과와 동결 (2026-10-16)

40단계의 답: 지금 엔진의 정밀도(llama.cpp · Q8_0 · 탐욕)에서 계산 손실은 답을 거의 다 바꾸지만 증상을 늘리지 않았다(한국어 다른 문자
36 ↔ 35, 수학 틀린 답 25 ↔ 28). 기울기는 되풀이 쪽에서만 승산 0.4 % 였다. 증상의 큰 몫은 모델 자신이 내고 스스로 키운다. 사용자는 이
연구를 동결하고, 결과를 실험 기록으로 정리해 밖에 알리기로 했다. GeulPU 는 사용자 개인의 쓰임을 위한 프로젝트로 바꾼다([40단계](40단계.md)).
