# 27단계 — 프롬프트의 타일 판: 텐서 파이프를 채운다 (2026-10-12)

26단계 끝에 남은 가장 큰 거리는 프롬프트다. 7B 의 프롬프트(2048 · 8192)는 llama.cpp 의 1.46 ~ 1.62 배(Q4_K_M · Q5_K_M) · 2.06 ~ 2.12 배(Q6_K)
· 1.23 · 1.38 배(Q4_0 — 23단계) 시간이다. 프롬프트 시간의 대부분은 행렬곱의 타일 판이다. 이 단계에서 타일 판이 텐서 코어를 더 채우게 한다 —
**계약은 바꾸지 않는다**(값이 비트까지 그대로인 바꿈만). 시험은 이 PC 안에서만 한다.

판정 기준을 결과보다 먼저 적는다.

## 진단 (이 문서보다 먼저 — 판은 바꾸지 않고 잰 것)

Nsight Compute 2026.3 으로 7B 층 0 의 실제 가중치 · 무작위 활성값, 행 1024(프롬프트 덩이)의 판 하나씩:

| 판 (가장 빠른 모양) | 시간 | 텐서 파이프가 일한 몫 | 주 반복의 명령 / 정수텐서곱 | 가장 큰 멈춤 |
|---|---|---|---|---|
| Q4_0 gate·up (세판, SwiGLU정수) | 2.96 ms | 58 % | 14.4 | 수학 파이프 막힘(math pipe throttle) |
| Q4_K gate·up (타일, SwiGLU정수) | 3.60 ms | 54 % | 13.8 | 〃 |
| Q6_K down (세판, 잔차) | 3.68 ms | 56 % | 16.8 | 〃 |

- 정수텐서곱(m16n8k32) 하나는 SM 의 네 갈래(SMSP)마다 텐서 파이프를 16 클록 잡는다. 판은 텐서곱 하나에 명령을 14 ~ 17 개 낸다 — 명령을 내는
  자리(갈래마다 클록당 하나)가 텐서 일과 거의 같은 크기다. ptxas 가 텐서곱을 몰아 놓아(여덟 개를 촘촘히, 그 사이에 명령 40 개쯤) 텐서 파이프가
  막히는 때와 쉬는 때가 갈린다 — 내는 자리도 텐서도 60 % 안팎에 머문다.
- 텐서곱 하나에 딸린 명령의 절반이 끝손질이다: 칸마다 블록마다 자리 합치기 · 정수→실수 · P·d 곱 · 곱해더하기(Q4_K 는 −w·b 의 곱해더하기 하나 더).
  정수→실수 바꾸기는 느린 파이프가 아니다(ptxas 가 I2FP 를 쓴다 — 26단계 끝에 적은 손잡이 3 의 가설은 틀렸다).
- Q6_K 는 아래블록(16 칸) 합을 따로 내려고 B 의 반을 가린 정수텐서곱을 두 번 한다 — 같은 이용률에서 쓸모 있는 일이 반이다. 아래블록 합
  T₁₆ 의 텐서곱과 칸마다의 −32·T 도 붙는다.
- SM 당 블록을 3 → 4 로(레지스터 한도 128) 하면 느려졌다(3.61 → 3.74 ms).

## 무엇을 만드나 (값은 그대로 — 계약을 바꾸지 않는다)

1. **Q6_K 타일 판.**
   - (가) B 를 부호 있는 q − 32 로 — 여섯 비트 값의 부호를 늘린다(낱말마다 명령 셋). 아래블록 합 T₁₆ 의 정수텐서곱과 칸마다의 −32·T 가 없어진다.
   - (나) 아래블록마다 **m16n8k16 정수텐서곱** — 글(geul) 언어 PTX 뒷단(글 저장소 `research/gpu` 의 `자체PTX/PTX.gl`)에 내장
     `정수텐서곱16`(mma.sync.aligned.m16n8k16.row.col.s32.s8.s8.s32)을 더한다. 지금 A · B 의 칸 차례에서는 스레드의 두 낱말이 같은 반에 있어
     k16 으로 나뉘지 않는다 — A 조각은 레인 짝끼리 바꿔(`정수레인에서받기`) 반마다 모으고(행 묶음마다 한 번 — 열 조각 여럿이 함께 쓴다), B 는
     반마다 낱말 하나를 읽는다. 엔진의 가중치 배치와 생성(줄 판)은 그대로다.
   - 텐서 일이 반이 되고 명령도 준다.
2. **Q4_0 · Q4_K 타일 판의 끝손질 — 마법수 누산.** 자리 1 의 정수텐서곱 s₁ 로 C = 256·s₁ + 마법수를 만들어(마법수는 블록의 정보에 이미 있는
   1.5·2²³·2^(E−13) 의 비트, Q4_K 는 거기서 8·T 를 뺀다) 자리 0 의 정수텐서곱의 누산 시작값으로 준다. 결과의 비트를 실수로 읽고 마법수
   (Q4_K 는 마법수 − 8·T·2^(E−13))를 빼면 u = S · 2^(E−13) — |S − 8T| ≤ 2²² 라 정확하고, 계약의 u(= v₁ + v₀)와 비트까지 같다. 칸마다 정수→실수 ·
   P·d 곱이 없어진다(끝손질의 명령 Q4_0 4 → 3, Q4_K 5 → 4). Q8_0 · Q5_K · Q6_K 는 |S| 가 2²² 를 넘을 수 있어 이 길을 쓰지 않는다.
3. (해 볼 것 — 빨라질 때만 넣는다) k-양자화 타일 판의 차례(앞 열 조각의 끝손질을 다음 조각의 텐서곱 사이에 — Q4_0 판과 같이)와 열먼저 판.
4. 바뀐 PTX 뒷단이 바꾸지 않은 모듈(0.5B · 7B Q8_0)을 바이트까지 같게 내는지 본다.

### 미리 밝혀 둘 것

1. **이 문서보다 먼저 한 것은 진단뿐이다**(위 표 — 지금 판의 Nsight 와 판 하나씩의 시간, 레지스터 한도 128 의 시도 하나). 바꾼 판은 아직 없다.
2. PTX 뒷단은 글 저장소(`geul-lang-v2`, `research/gpu`)의 것이다 — 그쪽에 고침(내장 하나)이 들어간다. 글ptx.py(파이썬판 — 대조용)에는 넣지
   않는다.
3. 마법수 길은 계약의 u 를 반올림 없이 만든다. 지금 판(fma(S, P·d, y))과 값이 같지만, P·d 가 아주 작아(블록 최댓값 2⁻¹⁰⁰ 아래쯤) 정확하지
   않을 때는 새 길이 계약에 더 가깝다 — 시험 활성값에서는 차이가 없다.
4. 27c 의 기준은 진단에서 낸 셈(Q6_K 판 1.5 ~ 1.9 배 빨라짐, Q4_0 · Q4_K 판의 명령 −14 %)보다 낮게 잡았다. Q8_0 은 바꾸지 않으므로 나빠지지만
   않으면 된다.
5. 프롬프트 8192 의 어텐션(Q4_0 474 ms — 8192 의 27 %)은 이 단계에서 다루지 않는다.
