# 36단계 — GeulPU 앱: 웹 화면 · 판(버전) 관리 · 릴리스

## 판정 기준 (만들기 전에 적음 — 2026-10-15)

### 왜
- 지금은 쓰려면 `git clone` → 스크립트(`runV.bat` · `speedV.bat` …) → 인자다. 친구 PC 넷 가운데 둘이 git 단계에서 멈췄고(34단계 —
  외장 드라이브 · 소유권 검사), 시험 하나를 바꿀 때마다 `git pull` 을 부탁해야 했다.
- 사용자(2026-10-15): 다른 환경에서 재현하거나 성능을 잴 때 벤치 프로그램처럼 화면에서 눌러 돌리고, 모델을 화면에서 받고, 채팅방을
  열어 실제로 써 보고 싶다. 쓰는 사람은 릴리스를 받아 실행하고 화면을 쓴다 — 판(버전)을 관리한다.

### 만드는 것
- **GeulPU.exe(관리자) — 글(geul) 언어로.** 두 번 누르면 `http://127.0.0.1:44544`(44544 = '글' 의 코드포인트 U+AE00)를 열고 브라우저를
  띄운다. 창을 닫으면 관리자와 그 아래 프로세스(추론 서버 · 도구)가 함께 꺼진다(일 객체). 가져오는 DLL 은 윈도의 것뿐(kernel32 ·
  ws2_32 · shell32 · winhttp) — GPU DLL(nvcuda · vulkan-1)은 관리자가 띄우는 서버 · 도구만 가져온다.
- **화면(web/)** — 바깥 자원 없는 HTML · JS · CSS 한 벌. 쪽: 채팅(대화방 · 흘림 · 멈춤) · 모델(목록 · 받기 · 확인 · 지우기 · 가진 파일
  더하기) · 벤치(자기 진단 · 속도 · 교차검증 · 결과 zip) · 장치 · 설정/정보(판 · 새 판 알림).
- **관리자의 일**
  - 장치 확인: Vulkan 장치 도구(34단계의 `장치V`)와 CUDA 장치 도구(새로)를 띄워 GPU · 드라이버 · 한도 · 협력 행렬 · 모듈 판(보통 ·
    공유32)을 읽고, GPU 층(자동: NVIDIA 이면 CUDA, 아니면 Vulkan — 설정에서 고름)을 정한다.
  - 모델: 목록(`models.json` — 파일 · 출처 · 크기 · SHA-256 · 확인 정도)에서 고르면 출처 · 크기를 보이고 사람이 누른 뒤에 받는다
    (WinHTTP · 이어받기). 받은 뒤 SHA-256(글의 `해시.gl`)으로 확인. 가진 GGUF 는 경로로 더한다(옮기지 않음). GGUF 의 설정 ·
    텐서 형식으로 이 엔진이 받는지(qwen2 · 머리 128 · Q8_0 / 순수 Q4_0 / k-양자화, 공유32 장치는 Q8_0 · Q4_0)를 먼저 본다.
  - 모듈: 모델의 모양 · 형식 · 장치(모듈 판 · 협력 모양)마다 생성기 → 뒷단(PTX · SPIR-V)으로 이 기기에서 만들고 자료 폴더에 둔다
    (판 기억도 그 옆에).
  - 추론 서버: 고른 모델로 띄우고(127.0.0.1 의 다른 포트) 화면의 `/v1/*` 를 그대로 넘긴다(흘림 포함). 화면과 같은 출처만 받는다
    (Host · Origin 확인 — 다른 웹사이트가 쓰지 못하게).
  - 벤치(한 번에 GPU 일 하나): 자기 진단(32단계), 속도(프롬프트 · 생성 토큰/초 — 서버의 `geulpu` 덧붙임 시간), 교차검증(R1 32 문제 —
    runV 와 같은 판정 · 같은 결과 꼴이라 `대조.py` 가 읽는다). 결과는 자료 폴더에 남고 화면에서 zip 으로 받는다(사용자 이름 · 경로를 지움).
- **자료 폴더** `%USERPROFILE%\GeulPU`(설정 · `GEULPU_HOME` 으로 바꿈) — 모델 · 모듈 · 결과 · 설정. 판을 바꿔도 그대로다.
- **서버의 두 가지 고침**(셈은 그대로): R1 토크나이저(교차검증이 빌드 때 덧대던 `토크나이저_R1.diff`)를 소스에, 채팅 틀에 R1 꼴
  (`tokenizer.ggml.pre = deepseek-r1-qwen`) — 화면에서 R1 과 채팅하려고. 서버 해시가 바뀌면 `expected.json` 의 빌드 기준을 새 빌드의
  값으로 적는다(출력 기준은 그대로 — 교차검증은 토큰으로 준 프롬프트의 completions 라 틀 · 토크나이저를 거치지 않는다).
- **판(버전)과 릴리스**
  - 앱 판은 SemVer, 이 단계가 `0.2.0`(0.1.0 은 14단계의 파이썬 판). 판은 `앱/판.gl` 하나에, 바뀐 것은 `바뀐것.md` 에.
  - 태그 `v0.2.0` 을 밀면 CI(`.github/workflows/release.yml`)가 그 커밋의 소스에서 빌드(글 컴파일러 고정점 → 뒷단 · 서버 · 도구 · 관리자 →
    진단 커널)해 `GeulPU-0.2.0-windows-x64.zip` 과 파일마다의 SHA-256(`version.json` · `SHA256SUMS.txt`)을 **초안 릴리스**로 올린다.
    공개는 사람이 한다. 같은 일을 이 PC 에서 하는 `앱/꾸리기.ps1`(올리지 않음).
  - 화면은 판 · 커밋을 보이고 GitHub 의 최신 릴리스와 견주어 새 판을 알린다(끌 수 있음). 한 번 누르는 업데이트는 그다음.

### 판정
- **36a 받고 실행(판정)**: 꾸린 zip 을 새 폴더에 풀고 GeulPU.exe 하나로 화면이 열린다 — git · 파이썬 · 빌드 · 인자 없이. zip 안
  실행 파일의 해시가 소스에서 빌드한 것과 같다(교차검증 기준 · 빠른 점검의 해시와 같은 바이트).
- **36b 화면으로 채팅(판정)**: 화면에서 모델을 더하고(가진 R1 · Qwen2.5-7B) 확인 → 서버 올림 → 채팅이 흘러나오고, 멈춤 · 새 대화가 된다.
  CUDA · Vulkan 둘 다(이 PC). 같은 질문의 탐욕 답이 서버에 바로 물은 것과 바이트까지 같다.
- **36c 화면으로 벤치(판정)**: 자기 진단 · 속도 · 교차검증이 화면에서 돌고 결과 zip 을 받는다. 교차검증은 줄인 판(문제 둘 · 토큰 64 —
  기준 글의 앞부분과 견줌)으로 길을 확인한다(전체 32 문제는 사용자가 허락하면).
- **36d 판 관리(판정)**: 화면에 판 · 커밋 · 빌드 날짜, 새 판 알림이 GitHub 의 최신 릴리스와 견준다. 릴리스 CI 가 초안까지 간다(태그를 밀고
  공개하는 것은 사용자가 정한다).
- **계약**: 엔진 · 커널 · 생성기는 바이트까지 그대로(빠른 점검), 바뀌는 서버(토크나이저 · 틀)는 교차검증의 completions 길로 R1 출력이
  기준과 같다.

## 결과 (2026-10-15, RTX 4070 Ti — 이 PC)

### 36a 받고 실행 — 통과
- `앱/꾸리기.ps1` 이 소스에서 모든 실행 파일 · 진단 커널을 빌드해(글 컴파일러가 빨라 3 초) zip(1.2 MB · 파일 25 개)을 만든다. 릴리스의
  실행 파일 다섯이 교차검증 기준과 같은 바이트: 생성기 b5bd6aea · PTX 뒷단 d2cd1276 · 서버(CUDA) 02ad42ad = server_r1 · SPIR-V 뒷단
  4e2dfc48 · 서버(Vulkan) 869f7f6d = server_r1_vulkan. R1 토크나이저를 소스에 넣은 서버가 교차검증이 덧대어 빌드하던 서버와 같은 바이트라
  교차검증 기준은 그대로다.
- zip 을 한글 · 띄어쓰기가 있는 새 폴더에 풀고 `GeulPU.exe` 하나로 화면이 열린다(장치 확인 0.3 초). 두 번째로 띄우면 먼저 뜬 것을 알아보고
  그 화면을 연다. 관리자를 끄면 그 아래 추론 서버도 함께 꺼진다(일 객체).
- 빠른 점검 모두 통과 — 모듈 아홉의 소스 · PTX · SPIR-V 가 바이트까지 그대로, 호스트 프로그램 35 개와 관리자 빌드, 관리자의 가져오기 표는
  kernel32 · shell32 · ws2_32 · advapi32 · bcrypt · winhttp 뿐.

### 36b 화면으로 채팅 — 통과
- 가진 R1 파일을 파일 고르기로 더하자 크기가 목록과 같아 SHA-256 을 저절로 재고(CNG 1.8 GB/s — 글로 쓴 SHA-256 은 49 MB/s 라 모델 확인에는
  윈도의 것을 쓴다) 목록의 R1 으로 이었다.
- R1(화면이 R1 틀을 짜 completions 로)과 Qwen2.5-7B(서버의 ChatML)가 화면에서 흘러나온다 — CUDA: 모듈 만들기부터 서버 준비까지 약 12 초,
  R1 115 토큰 59.9 토큰/초. Vulkan(협력 16x16x32): 서버 준비 6.6 초, R1 의 생각이 흐르는 중에 멈춤이 된다.
- 관리자를 거친 탐욕 답과 서버에 바로 물은 답이 바이트까지 같다(Qwen2.5-7B "한국의 수도는 서울입니다.").
- 지킴: 다른 출처의 쓰기 요청 · Host 가 다른 요청은 403.

### 36c 화면으로 벤치 — 통과
- 속도(CUDA, 슬롯 1 · 문맥 4096): 프롬프트 512 85.2 ms · 2048 364.1 ms, 생성 토큰당 16.61 ms(짧은 문맥) · 16.77 ms(문맥 1024 뒤) —
  34단계의 CUDA 기록(2048 357.7 ms · 생성 16.5 ms)과 같은 급. 서버의 `first_token_ms` 는 28단계부터 µs 였다(이름만 ms — 앱이 µs 로 읽는다).
- 자기 진단(Vulkan · 협력 16x16x32, 59 초): 대역 490.0 GB/s · 협력 정수 텐서 145.8 TOPS · 생성 바닥의 1.14 배 · 슬롯 여덟 걸음 1.32 배 · 프롬프트
  2048 2.01 배.
- 교차검증 줄인 판(문제 둘 · 토큰 64): CUDA — 빌드 해시 셋 · 모듈 소스 · PTX 해시가 기준과 같고 2/2. Vulkan — 빌드 해시 셋 · 이 PC 에서 새로
  만든 협력(16x16x32) · 기본 모듈의 소스 · SPIR-V 해시가 기준과 같고(SPIR-V 뒷단 3 · 5 초) 두 모듈 2/2. 결과 zip 이 올바르고(UTF-8 이름 ·
  사용자 경로 없음) `대조.py` 가 그대로 읽어 걸음마다 로짓 해시 128 걸음이 기준의 앞부분과 같다고 판정한다. 전체 32 문제는 돌리지 않았다
  (모듈마다 15 분 남짓 — 사용자가 정할 일).
- 받기: 이 PC 안의 시험 서버(http, 이어받기)로 0.5B 파일을 받다가 200 MB 에서 끊자 Range 로 나머지 475.7 MB 를 이어받고 SHA-256 을 맞춰
  모델로 더했다(0.5B 는 '받지 않는 모양' 으로 보인다). 바깥(Hugging Face)에서는 받지 않았다.

### 36d 판 관리 — 부분(릴리스 CI 는 밀어야 돈다)
- 화면에 판 · 커밋 · 빌드 때(릴리스의 version.json), 새 판 알림은 GitHub 의 최신 릴리스(v0.1.0)와 견준다 — 지금 판이 더 새로워 띠를 보이지
  않는다.
- 릴리스 CI(`.github/workflows/release.yml`)는 태그를 밀면 돈다 — 손으로 돌리기(아티팩트만)와 태그(초안 릴리스)는 사용자가 정한다.

### 36e 디자인 · 사용성 — x.ai 디자인 시스템, 독립 평가를 되풀이 (2026-10-15)
- 사용자(2026-10-15): 화면이 정돈되지 않은 전형적인 'AI 느낌'이다 — Claude 앱 · LM Studio 처럼 깔끔하고 직관적인 아이콘 중심으로, 완전한
  어둠을 기본으로 강조색 하나. 주 디자인 시스템은 x.ai(`npx getdesign@latest add x.ai` 가 설치하는 DESIGN.md — [앱/DESIGN.md](../앱/DESIGN.md),
  VoltAgent/awesome-design-md · MIT). 완성한 뒤에는 독립 에이전트가 디자인 · 사용성을 객관적으로 평가하고, 그것을 고치기를 되풀이한다.
- 해석(app.css 머리말): 바탕 #0a0a0a · 카드 #191919 · 선 #212327, 흰 반투명 외곽 알약이 기본이고 흰 채움 알약은 화면마다 하나, 굵기 400,
  강조색 선셋 오렌지 #ff7a17 은 '지금 움직이는 것'(진행 · 도는 상태 · 지금 위치 · 키보드 초점)에만 — 고른 것 · 켠 것은 흰색 · 밝은 회색,
  판정의 성공 · 실패만 초록 · 빨강(빨강엔 늘 경고 아이콘). 알약은 누르는 것에만, 상태 꼬리표는 4px 옅은 채움. 아이콘은 앱에서 그린 24 격자
  선 아이콘 한 벌, 모델은 종류 아이콘(추론 · 코드 · 일반). 영문 · 숫자 라벨(양자화 등)은 고정폭 대문자, 간격은 4의 배수, 글자 크기는 아홉 단계.
  입력 칸 테두리는 바탕과 3:1 이상. 바깥 자원(글꼴 · CDN)은 쓰지 않는다.
- 방법: 고칠 때마다 headless Chrome 을 DevTools 프로토콜로 몰아 장면 25 개를 찍고(시험 대화는 임시 프로필에만), 매번 **새** 독립 에이전트가
  스크린샷 · 코드 · 모의 API 로 평가한다(살아 있는 앱에는 GET 만). 점수(10점): 1차 6 → 2차 5.5(실제 R1 출력을 넣어 보아 더 엄격해짐) →
  3차 6.5 → 4차 6(흐르는 중 다시 그리기 결함을 찾음) → 5차 6.5(연필이 대화를 지우는 결함을 찾음) → 6차 6.5(좁은 창에서 알림이 잘림).
  5차 평가는 Windows 업데이트의 자동 다시 시작(10-15 05:59, KB5127648)에 끊겨 처음부터 다시 돌렸다. 6차의 지적을 고친 뒤 7차 평가는
  사용자의 뜻(2026-10-15)대로 모델 다양성을 늘리는 일을 마친 뒤에 정한다.
- 평가가 찾은 실제 결함과 고침:
  - 화면에 "null" 이 찍힘(자식 갈기에 null), 설정 칸이 1초마다 지워짐, 상태 막대가 1초마다 키보드 초점을 빼앗음(칸을 갈아 끼움 → 제자리 고침),
    휴대폰 너비에서 위 막대가 위로 밀려 사라짐(#main 의 자동 최소 높이).
  - **R1 의 생각이 접히지 않았다.** 서버는 토큰 종류 1(보통)만 글로 내는데 R1 의 `<think>` · `</think>`(151648 · 151649)는 종류 4(사용자
    정의)라 빠진다 — llama.cpp 는 종류 4 를 글로 낸다. 교차검증 응답 64 개의 토큰 번호를 GGUF 어휘로 풀어 보니 보통 토큰만 풀면 서버 글과
    64/64 같고, `</think>` 가 있는 40 개 모두 첫 "\n\n\n" 이 바로 그 경계였다(앞서 나온 곳 0, 24 개는 3200 토큰에서 생각 중에 끝남). 화면이
    이 경계와 흘림 끝의 토큰 번호(151649 가 있는가)로 생각과 답을 나누고, 다음 차례에는 앞 답의 생각을 다시 보내지 않는다. 서버가 종류 4 를
    글로 내게(켜는 꼴로) 고치면 서버 해시가 바뀌어 교차검증 기준을 다시 적어야 하므로 사용자가 정할 일로 남겼다.

- 목록의 모델은 CUDA(이 PC)에서만 돌려 보았다(36f) — Vulkan · AMD 에서 이 파일들은 아직이다.
- 공유 메모리 32 KB GPU(Windows 의 AMD) · 그래픽 메모리 8 GB 이하에서는 지금 돌릴 수 있는 파일이 없다(Q8_0 7B 는 10 GB 이상, 흔한 Q4_0 파일은
  출력이 Q6_K 라 엔진이 받지 않음, k-양자화는 이 GPU 미지원).
- 글꼴(Pretendard · Geist Mono — OFL)은 넣지 않았다(내려받기라 사용자가 정한다) — 지금은 PC 에 있는 글꼴로 그린다.
- 추론 서버(관리자 아래 127.0.0.1 의 다른 포트)는 예전처럼 CORS `*` 를 낸다 — 관리자는 같은 출처만 받지만 서버 포트를 직접 맞히는 웹사이트는
  막지 못한다. 서버에 출처 막기를 넣으면 서버 해시가 바뀌므로 다음에.
- 서버의 `/v1/chat/completions` 는 ChatML 틀만 쓴다 — R1 의 틀은 화면이 짠다(바깥 프로그램이 R1 과 채팅하려면 completions 로).
