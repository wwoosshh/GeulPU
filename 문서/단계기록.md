# 단계 기록 — GeulPU 가 나오기까지 (연구 0~14단계, 2026-10-08 ~ 10-10)

연구는 글 저장소의 `research/gpu` 가지에서 했다. 단계마다 판정 기준을 실험보다 먼저 적고(커밋으로 남김), 모든 변형을 비트 대조한 뒤에
시간을 적었으며, 실패한 시도와 기준 미달도 그대로 남겼다. 전문:
[docs/17 — 연구: 의미를 지키는 GPU 컴파일러](https://github.com/wwoosshh/geul-lang/blob/research/gpu/docs/17-연구-의미를-지키는-GPU-컴파일러.md) ·
[research/gpu/](https://github.com/wwoosshh/geul-lang/tree/research/gpu/research/gpu) (단계마다 README · 결과 JSON · 재는 스크립트).
14단계부터는 이 저장소(GeulPU)에서 한다.

## 남은 것 (15단계 끝)

- 생성은 바닥의 1.21배 — 데우는 블록이 장벽이 풀린 것을 늦게 알아차리는 시간(층마다 1~4 µs), 데우기 읽기 뒤의 어텐션 지연, C · D 의 입력 바꾸기를
  블록마다 되풀이하는 몫, 로짓(바닥의 1.07배)이 남았다.
- 이 GPU 에서 미리읽기 명령(prefetch.global.L2 · cp.async)은 L2 에 거의 남지 않는다 — 32 바이트마다 실제로 읽어야 한다(15단계 밝혀 둘 것 2).
- 프롬프트 8192 의 어텐션, 더 많은 모델 모양, k-양자화, 샘플링, Linux. 글 쪽: 네이티브 컴파일러의 PTX 뒷단, 호스트를 글로.

## 남은 것 (14단계 끝)

- 생성은 바닥(가중치 한 번 읽기 1.04 ms)의 1.56배 — 커널 147 개의 띄움 사이와 작은 행렬곱의 지연. 생성 메가커널로.
- 프롬프트 8192 의 어텐션(층마다 3.4 ms)이 가장 큰 몫 — 계약의 산수(적힌지수 · e′ 자리)가 정하는 명령 수.
- 더 많은 모델 모양(머리 128 · 다른 너비), k-양자화, 샘플링, Linux.

## 남은 것 (13단계 끝)

- 문맥 10만 가까이의 생성은 llama.cpp 와 1% 안팎 — 두 엔진 모두 실제 읽기 대역 가까이에 있다(글의 KV 는 지수 바이트만큼 1.6% 크다).
  생성 메가커널의 단계 사이(장벽 · 접는 블록의 꼬리)를 줄여야 한다.
- 타일 효율(int8 최고치의 53%)과 프롬프트 어텐션(바닥의 2.3~2.9배)은 계약의 산수가 정하는 명령 수에 묶여 있다.
- 다음: Llama 계열 블록 세트(RoPE · RMSNorm · SwiGLU · GQA · 머리 128)로 첫 채팅 모델, 터미널 실행기.
