# 25단계 — 층 나누기: 여러 GPU 에 모델을 나눠 싣기 (2026-10-11)

사용자 방향(23 · 24단계에 적은 것): 실제로 쓰는 사람들은 VRAM 50 ~ 100 GB 의 작은 서버급, 그리고 대형 서버에서 32B · 72B · 120B 를 돌린다.
추천 순서의 (3)이 이 단계다 — 한 GPU 에 들지 않는 모델을 층으로 나눠 여러 GPU 에 싣는다. **이 PC 에는 GPU 가 한 장뿐이다.** 그래서 한 GPU
안에서 여러 장을 흉내 낸다: 조각마다 CUDA 문맥을 따로 만들고(메모리 · 모듈 · 그래프가 따로), 조각 사이의 넘김은 실제 여러 GPU 에서 쓰는
피어 복사(`cuMemcpyPeer`)로 한다. 같은 코드가 장치 번호만 바꾸면 여러 GPU 에서 돈다.

판정 기준을 결과보다 먼저 적는다.

## 무엇을 만드나

1. **엔진의 층 범위**: 엔진 하나(조각)가 층 [시작, 끝)만 싣는다 — 그 층의 가중치 · KV 캐시만. 첫 조각은 임베딩, 끝 조각은 마지막 RMS · 로짓 ·
   가장 큰 번호를 맡는다. 조각 사이로는 잔차 흐름(행 × 너비 짧은실수)만 넘긴다.
2. **조각 여럿(호스트, 글)**: 조각마다 문맥(장치 번호를 받는다 — 이 PC 에서는 모두 0) · 모듈 · 판 고르기 · 그래프. 프롬프트 덩이는 조각 0 →
   1 → … 차례로, 생성은 토큰마다 조각의 그래프를 차례로 띄우고 잔차 · 다음 토큰 · 걸음을 넘긴다. 나누는 자리는 장치마다의 메모리 예산에 맞춰
   층의 바이트로 고른다(예산은 장치의 남은 메모리, 흉내 낼 때는 주는 값 — "12 GB 를 6 GB 둘처럼").
3. **실행기 · 시험 · 재기 도구**: `--나누기 P`(장치 0 에 P 조각 — 흉내) · `--장치 0,1,…` · `--예산 GB` 를 받는다.

## 판정 (미리 정함)

| 판정 | 기준 (미리 정함) | 상태 |
|---|---|---|
| 25a 비트 | P 조각(조각마다 문맥 — 이 PC 에서는 모두 장치 0)으로 나눠 돌린 로짓과 KV 캐시가 한 조각(23 · 24단계의 길)과 비트까지 같다 — 7B Q8_0 · 7B Q4_0 은 P = 2 · 3 · 4, 14B Q4_0 은 P = 2 · 3 (조각마다 일 버퍼가 따로라 넷은 12 GB 한 장에 들지 않는다), 모두 채팅 질문 셋 + 2100 토큰, 다섯 길. 합성 72B Q4_0(층 넷)은 P = 2 · 4 (넷은 조각마다 층 하나, 정한 무작위 토큰열 셋 + 2100). 다섯 길 각각이 한 조각의 요약(로짓 해시 · 토큰 · KV 해시)과 같아야 한다 | |
| 25b 예산 | 조각마다 예산 6 GB(흉내)를 주면 14B Q4_0(가중치 8.3 GB)은 한 조각에 들지 않고(알린다), 두 조각으로 나눠 돈다 — 그 출력이 25a 와 같다(다섯 길 요약이 한 조각과 같다) | |
| 25c 넘김의 값 | 생성(토큰당, 문맥 짧을 때 · 2048 · 8192) 시간의 비 t(P 조각) / t(한 조각) — 같은 GPU 에서. **통과: 14B Q4_0 · 7B Q4_0 의 P = 2 가 셋 모두 1.03 이하.** P = 3 · 4 와 프롬프트의 비는 기록 | |

판정이 아닌 기록: 조각마다의 층 수 · 장치 메모리, 넘김 한 번의 시간(잔차 복사 · 문맥 바꾸기), llama.cpp 의 층 나누기(`--split-mode layer`)와의
견주기는 이 PC 에 GPU 가 한 장이라 하지 않는다.

### 미리 밝혀 둘 것

1. **이 PC 의 결과는 흉내다.** 조각들이 한 GPU 를 나눠 쓰므로 메모리는 물리적으로 합쳐 12 GB 이고(예산으로 나눠 센다), 피어 복사는 같은 장치 안의
   복사다. 실제 여러 GPU 의 넘김은 PCIe · NVLink 를 지나 더 오래 걸린다 — 25c 는 소프트웨어 쪽의 값(동기화 · 복사 · 띄움)을 잰다.
2. **32B · 72B 의 실제 모델은 이 단계에서도 돌리지 않는다**(합친 메모리가 12 GB). 층 나누기의 길(비트)은 합성 72B 와 실제 7B · 14B 로 본다.
3. **처음 판은 조각을 차례로 돌린다**(한 흐름의 생성에서 층 나누기는 원래 차례다). 여러 요청을 겹쳐 돌리는 파이프라인은 (4)의 서버 기능에서.
4. **대조 도구는 파이썬이다**(대조 · 모음). 엔진 · 실행기 · 시험 · 재기 도구는 글이다.
