# 15단계 — 생성 메가커널: Qwen2 의 생성을 바닥 쪽으로 (2026-10-10)

사용자 결정(같은 날, 14단계 보고 뒤): "15단계 — 생성 메가커널". 이 문서는 연구 계획이다. 판정 기준을 결과보다 먼저 적고(이 커밋),
결과가 나오면 상태 칸만 고친다([단계기록](단계기록.md)의 규칙 그대로).

## 왜

14단계의 생성(토큰 하나)은 **고치지 않는 CUDA 그래프 하나**다. 층마다 커널 여섯, 토큰마다 147 개다. 공식 시간은 1.623 · 1.695 ·
1.999 ms/토큰(채팅 질문 · 문맥 1024 · 8192)이다. 바닥은 다음과 같다.

- 가중치를 한 번 읽기: 525 MB ÷ 504 GB/s = **1.041 ms**.
- 문맥 8192 는 KV 를 더한다. 위치마다 층 24 × KV 머리 2 × 260 바이트이므로 **1.244 ms**.

채팅 질문의 생성은 바닥의 1.56 배다.

## 판정 전에 잰 것 — 14단계 생성 그래프의 시간 나누기

방법: 생성 그래프에서 커널 종류 하나만 남긴 그래프의 시간, 그리고 그 종류만 뺀 그래프와의 차를 잰다(층 24 개 모두 — 실제 DRAM 읽기,
값은 틀린다 — 재는 데만).

| 커널 (층마다 하나) | 채팅 질문: 그것만 | 채팅: 빼면 줄어듦 | 문맥 8192: 그것만 | 8192: 빼면 줄어듦 | 바닥(DRAM, 층 24) |
|---|---|---|---|---|---|
| 정수줄선형QKV (RMS · QKV · RoPE · KV) | 0.103 ms | 0.182 | 0.103 | 0.161 | 0.052 ms (1.1 MB × 24) |
| 정수조각어텐션 | 0.152 | 0.185 | 0.471 | 0.483 | 0.203 ms (8192) |
| 정수조각접기 | 0.051 | 0.086 | 0.096 | 0.107 | — |
| 정수줄선형o (+ 잔차) | 0.059 | 0.124 | 0.060 | 0.099 | 0.040 |
| 정수줄선형gu (RMS · gate·up · SwiGLU) | 0.534 | 0.564 | 0.535 | 0.539 | 0.441 (9.26 MB × 24) |
| 정수줄선형down (+ 잔차) | 0.320 | 0.354 | 0.321 | 0.332 | 0.220 |
| 로짓 (RMS · 로짓 · 블록마다 가장 큰 값) | 0.317 | 0.345 | 0.317 | 0.319 | 0.288 (145 MB) |
| 전체 (147 커널) | 1.649 ms | | 1.996 ms | | 1.041 · 1.244 ms |

읽은 것:

- **작은 단계는 지연에 묶여 있다.** QKV · 어텐션 둘 · o 를 빼면 채팅에서 0.58 ms 가 준다. 그런데 그들의 DRAM 바닥은 0.09 ms 다.
- **큰 행렬곱도 바닥에 못 미친다.** gate·up 은 415 GB/s, down 은 348 GB/s 다 — down 은 블록 180 개가 저마다 4864 칸의 입력을 자리로 바꾼다.
- **문맥 8192 에서는 어텐션이 가장 크다.** 0.47 ms 로, KV 바닥 0.20 ms 의 2.3 배다. 질의 머리 일곱이 KV 머리 하나를 따로따로 읽는다.

## 할 것

**생성메가qwen** — 토큰 n 개의 생성 전체를 협력 실행 한 번으로 한다. 블록 G 개(SM 60 × 2)가 모두 함께 올라 있고, 단계 사이는 격자
장벽이다(GPT-2 생성메가와 같은 원자더하기 · 획득읽기).

- **단계** — 층마다 다섯:
  1. QKV — RMS · RoPE · KV 바꾸기를 묶은 판과 같은 계산.
  2. 어텐션 — (질의 머리, 조각 묶음)을 블록들이 나누고, 머리마다 마지막에 도착한 블록이 접는다(두 층 접기).
  3. o + 잔차.
  4. gate·up — RMS · SwiGLU.
  5. down + 잔차.
- **토큰 끝** — 로짓(RMS · 블록마다 가장 큰 값) → 장벽 → 블록 하나가 다음 토큰을 고르고 그 임베딩을 숨칸에 둔다 → 장벽.
- **겹치기** — 일이 없거나 일을 마친 블록은 다음 단계들의 가중치를 L2 로 미리 올린다(값과 상관없다). 작은 단계의 지연 동안 DRAM 이
  쉬지 않게 하려는 것이다.
- **산술** — 단계마다 줄 길의 묶은 판(14단계)과 같은 식 · 같은 차례다. 그래서 비트가 같다.
- **더 줄일 것** — 재서 고른다. 값은 모두 같은 계약이다.
  - down 의 입력 자리를 gate·up 단계가 바로 쓰기.
  - o 의 입력 자리를 접는 블록이 바로 쓰기.
  - GQA — KV 머리 하나의 조각을 질의 머리 일곱이 함께 읽기.
- **엔진** — `생성` · `이어생성` 이 메가커널을 쓴다(실행기는 끝 토큰이 나오면 커널 안에서 멈춘다). 14단계의 생성 그래프는 대조용으로 남긴다.

## 결과 (2026-10-10)

### 만든 것

- **생성 메가커널** `생성메가qwen` ([커널생성.py](../커널/커널생성.py)): 토큰 n 개의 생성 전체를 협력 실행 한 번으로 한다.
  - 블록 120 개(SM 60 × 2, 256 스레드, 레지스터 124, 넘침 0)가 모두 함께 올라 있고, 단계 사이는 격자 장벽이다.
  - 층마다 단계 다섯이다(조각이 둘 이상이면 어텐션이 둘). 산수는 14단계 줄 길의 묶은 판과 같은 식 · 같은 차례라 비트가 같다.
- **어텐션 — GQA 무리 일감** (`정수조각계산머리들`): 워프 하나가 (조각, 같은 KV 머리를 읽는 질의 머리 H 개)를 맡는다. 키 · 값 조각은 무리마다
  한 번 읽는다.
  - H 는 실행 때 고른다. 일감 수가 워프 수(960) 안에 드는 가장 작은 것(1 · 2 · 3 · 4 · 7)이다 — 채팅 질문 · 문맥 1024 는 1, 8192 는 3.
  - 레지스터가 넘치지 않게 머리 고리를 다섯으로 나눴다: 키 ta 의 점수, 키 ta + 1 의 점수, 최댓값 · 지수 · e′, 값 d 둘의 가중합.
- **접기**: 조각이 하나면 o / l 을 바로 낸다. 두 층 접기는 조각이 하나면 O / L 그대로라 같은 비트다.
  - 조각이 둘 이상이면 장벽 뒤 머리마다 블록 하나가 접는다(`메가두층접기`). 묶음은 워프들에 나누고, 식 · 차례는 정수접기와 같다.
- **데우기** (`메가데우기`): 장벽에서 기다리는 블록이 다음에 읽을 가중치를 **실제 읽기**로 L2 에 올린다. 읽은 값은 XOR 로 모아 버리므로 값과
  상관없다. 바퀴마다 장벽이 풀렸는지 보며 블록마다 32 바이트 조각 256 개(8 KB)씩 읽는다.
  - P1 · P2 · B 의 장벽: 제 C(gate · up) 묶음(척도 · 값), 그다음 제 D(down) 묶음.
  - C 의 장벽: 제 D 묶음.
  - D 의 장벽: 다음 층의 QKV · o 의 몫.
- **엔진** ([엔진/글qwen2.py](../엔진/글qwen2.py)): `생성` · `이어생성` 이 메가커널을 쓴다. 실행기는 끝 토큰이 나오면 커널 안에서 멈춘다.
  - 14단계의 생성 그래프는 `메가쓰기 = False` 로 남아 대조에 쓴다.
  - 메가커널은 최대길이 16384 까지다(두 층 접기의 묶음 16 개). 넘으면 그래프로 간다 — 같은 비트.
- **시험** [시험/메가15.py](../시험/메가15.py) (15a) · **재기** [재기/재기15.py](../재기/재기15.py) (15b~15d).

### 밝혀 둘 것

1. **어텐션의 꼴이 계획과 다르다.** 계획은 "(질의 머리, 조각 묶음)을 블록들이 나누고, 머리마다 마지막에 도착한 블록이 접는다" 였다.
   - 그 꼴(첫 판)은 문맥 8192 에서 층마다 어텐션 27.75 µs 였다. 질의 머리 일곱이 같은 KV 를 따로 읽고, 접기를 블록 하나가 몰아서 했다.
   - 위의 GQA 무리 일감 · 나눈 접기로 바꿨다. 첫 판의 꼴은 `메가어텐션 = "옛"` 으로 남겼다(재는 데만).
2. **미리 읽기 → 데우기.** 계획은 "일이 없는 블록이 다음 가중치를 L2 로 미리 올린다" 였다. 재 보니 이 GPU 에서 미리읽기 명령은 L2 에 거의
   남지 않았다. 9 MB 를 읽는 커널의 시간은 다음과 같았다(같은 실행 안):

   | 앞서 한 것 | 읽기 시간 |
   |---|---|
   | 차가움 | 45.1 µs |
   | prefetch.global.L2 (128 B 마다) | 43.0 µs |
   | cp.async 16 B (32 B 마다) | 43.0 µs |
   | 실제 4 바이트 읽기 — 128 B · 64 B · 32 B 마다 | 40.7 · 34.8 · 28.6 µs |
   | 데움 | 28.5 µs |

   - 32 B 조각마다 실제로 읽어야 다 남는다.
   - 또 노는 블록이 미리읽기를 한꺼번에 쏟으면 DRAM 줄이 막혀 급한 단계가 늦어졌다. 채팅 질문에서 P1 이 3 → 9.25 µs, 어텐션이 4.25 → 7.25 µs
     였다.
   - 그래서 기다리는 블록이 바퀴마다 조금씩 실제로 읽게 했다. 값과 상관없는 것은 같다.
   - 미리읽기 명령(힌트)은 작은 묶음(B 의 o · 다음 층 P1 · 로짓의 다음 묶음)에만 남겼다.
3. **"더 줄일 것" 셋.**
   - "GQA — KV 머리 하나의 조각을 질의 머리 일곱이 함께 읽기"는 했다(1).
   - "down 의 입력 자리를 gate·up 단계가 바로 쓰기"는 해 보았으나 느려서 껐다(`메가C자리`). 출력 32 개 묶음이 152 개라 블록 120 개에 두 바퀴가
     된다.
   - "o 의 입력 자리를 접는 블록이 바로 쓰기"는 하지 않았다.
4. **재서 버린 것**(값은 모두 같다 — 깃발로 남겼다): 채팅 질문의 토큰당이다.
   - C · D 의 행렬곱에서 쌍을 먼저 모두 읽기(`메가CU` · `메가큰U`): 1.434 → 1.554 ms. DRAM 에 묶인 단계라 한꺼번에 띄운 읽기가 해롭다.
   - P1 의 같은 것(`메가P1U`): 데우기 전에는 0.5% 빨랐지만(1.4415 → 1.4336 ms), 데우기가 들어온 뒤에는 1.1% 느려(1.269 → 1.283 ms) 껐다.
   - C 의 들머리에서 D 묶음 미리읽기(`메가D먼저`): 끄니 1.293 → 1.276 ms.
   - 데우기에서 o 를 C 보다 먼저(`메가데우기o`): 1.280 → 1.323 ms.
   - 어텐션 일감 블록은 P1 장벽에서 쉬기, 다음 층 KV 데우기: 각각 0.6 · 0.5% 느렸다.
   - 데우는 스레드 64 · 128 · 256 개: 1.433 · 1.373 · 1.340 ms (256).
5. **시험을 위해 엔진을 고친 것.** `생성로짓` 이 최대행보다 긴 프롬프트를 나눠 넣는다(`생성` 과 같이). 15a 의 문맥 2100 · 8192 를 최대행
   2048 의 엔진으로 재려고 했다. 나눠 넣기는 계약이라 값은 같다.
6. **개발 중 찾은 것 — 장벽의 셈.** 첫 데우는 장벽은 스레드마다 장벽수를 셌는데, 옛 장벽은 스레드 0 만 셌다. 둘이 섞이자 스레드마다 장벽이
   풀렸다는 판단이 갈려 커널이 멈췄다(개발 중 — 공식 측정 전). 지금은 모든 장벽에서 모든 스레드가 세고, 풀렸는지는 스레드 0 이 판에 적어
   함께 본다.
