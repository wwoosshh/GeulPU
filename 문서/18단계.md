# 18단계 — 호스트를 글로: 글 컴파일러와 CUDA 드라이버만으로 (2026-10-10)

사용자 결정(같은 날, 17단계 뒤): "호스트부터 진행해 — 다른 언어의 종속없이 글컴파일러와 cuda dll만 통해서 작동하도록 구성해야해".

17단계 뒤의 자리: GPU 에서 도는 코드(PTX)는 글 컴파일러가 낸다. 그것을 부르는 호스트 — GGUF 읽기, 가중치를 엔진의 배치로 깔기, RoPE 표,
토크나이저, 커널 띄우기 · CUDA 그래프 · 생성 메가커널, 터미널 실행기 — 는 파이썬(numpy · ctypes · decimal · unicodedata)이다. 이 단계는
호스트를 글로 옮겨, 자체 호스팅 글 컴파일러가 빌드한 실행 파일 하나가 GGUF 와 PTX 를 읽어 nvcuda.dll 만으로 채팅하게 한다. 판정 기준을
결과보다 먼저 적는다.

## 할 것

글 호스트(GeulPU `호스트/*.gl`) — 자체 호스팅 컴파일러(geul-lang-v2 `build/self_컴파일러.exe`, 17단계의 고정점)로 빌드한다. 파이썬 호스트의
계산을 같은 정의로 옮긴다:

- **쿠다** — nvcuda.dll 의 드라이버 API 를 외부 선언으로: 모듈 · 함수 · 메모리 · 실행 · 협력 실행 · 그래프(마디 고치기) · 이벤트 · 점유.
- **GGUF v3 읽기** — 메타데이터 · 텐서 표 · 날 바이트.
- **가중치** — 정수 배치(`gguf읽기.깔기정수`, Q8_0)와 엔진의 차례(q · k · v 를 열로 잇기, gate · up 을 32 열마다 번갈아, 층마다 [값][척도]).
- **RoPE 표** — `계약/정수계약.rope표` 와 같은 정의: θ_i = θ^(−2i/64) 를 fp64 로 바르게 반올림, 각 = 위치 · θ_i (fp64 곱 하나), cos · sin 을
  짧은실수로 바르게 반올림. 파이썬판의 decimal 대신 글로 쓴 두 배 정밀도(double-double) 계산과 반올림 경계의 검사로.
- **토크나이저** — 특수 토큰 떼기 · NFC 정규화 · Qwen2 정규식(손으로 편 것) · 바이트 BPE(GGUF 안의 낱말 · 병합) · 잇기. 유니코드 표(일반 범주
  L · N, NFC 의 분해 · 결합 자료)는 유니코드 15.0.0 의 UCD 파일(파이썬 3.12 의 unicodedata 와 같은 판)을 글 프로그램이 읽어 글 소스로 만든다.
- **엔진** — `글Qwen2` 의 계산: 판 고르기(재서), 계획(행 다섯 이상은 타일 판 · 넷까지는 줄 판, 어텐션 판 고르기, 꼬리 자르기), CUDA 그래프
  (위치 마디 고치기), 생성 메가커널 — 같은 커널을 같은 매개변수로.
- **실행기** — 채팅(ChatML, 차례마다 KV 캐시 잇기, 흘려 보이기, 끝 토큰에서 커널 안에서 멈춤), 그리고 시험 · 재기 모드.

파이썬 호스트(`엔진/` · `실행.py`)는 대조용으로 남긴다.

### 미리 밝혀 둘 것

1. **커널 모듈의 소스는 아직 파이썬 생성기가 만든다.** 실행기가 읽는 PTX 는 글 뒷단이 `qwen2Q8.gl` 에서 만든 것인데, 그 글 소스는
   `커널/커널생성.py` 의 출력이다 — 생성기를 글로 옮기는 것은 다음 단계(19단계)다.
2. **유니코드 표의 출처.** UCD 파일(unicode.org 의 유니코드 15.0.0 `UnicodeData.txt` · `CompositionExclusions.txt`)을 내려받아야 한다 —
   사용자의 허락을 받아서. 표를 만드는 것도 글 프로그램이다.
3. **정답지는 파이썬 호스트다.** 18b ~ 18e 는 파이썬 호스트와 견준다. 견주는 도구(두 호스트를 돌려 해시 · 시간을 모으는 스크립트)는 파이썬이어도
   된다 — 실행기가 도는 데에는 들지 않는다.
