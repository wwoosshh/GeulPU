# 33단계 — 같은 최적화에서 계약의 값

## 판정 기준 (실행 전에 적음 — 2026-10-14)

### 왜
- README 가 스스로 적었다: "결정성(어느 길로 계산해도 같은 비트) 자체와 CPU 참조와의 비트 같음이 같은 최적화에서 셈을 얼마나 더하는지는
  아직 따로 재지 않았다."
- 사용자의 기준(2026-10-13): 같은 최적화의 값이 1.01 쯤이면 괜찮고, 1.2 ~ 1.3 배면 할 가치가 없다.
- 사용자의 원칙: 같은 최적화의 일끼리만 견준다(100 대 100). llama.cpp 를 커널 솜씨로 이기는 것은 전제의 증명이 아니다.
- 30단계 끝에서 이것을 31단계로 잡았다가 Vulkan 에 밀렸다. 사용자와 정한 차례(2026-10-14)로 Vulkan · 32단계의 속도 작업보다 앞에 둔다.

### 무엇을 견주나 — 같은 판에서 하나씩 끈다
계약의 제약을 하나씩 끈 모듈을 같은 생성기로 만든다. 판의 모양 · 합치기(융합) · 띄우는 차례 · 그래프는 V0 과 같다. 바뀌는 것은 끈 제약의
셈뿐이다.

| 변형 | 끄는 것 | 남는 것 | 무엇의 값 |
|---|---|---|---|
| V0 계약 | — | — | 기준 |
| V1 자리 하나 | 선형층(타일 판 · 줄 판 · 줄 타일 판 · 로짓 판)의 활성값을 자리 하나로. 계약의 식 그대로 P = 8 · 1 − 3 = 5 — 격자 2^(E − 5), \|n\| ≤ 64 (llama.cpp 의 8 비트 활성값과 같은 급) | 어텐션 · 그 밖은 V0. 정수 합 · 정해진 차례 | 계약의 정밀도(자리 둘)의 값 |
| V2 하드웨어 셈 | CPU 와 비트까지 같음: 적힌 지수 → 근사 지수(ex2.approx), 나눗셈 · 제곱근 → 근사 명령, `.rn` 을 풀어 곱 · 더하기의 합치기를 드라이버에 맡긴다 | 자리 둘 · 정수 합 · 정해진 차례 — 한 GPU 안의 결정성 | CPU 비트 같음의 값 |
| V3 | V1 + V2 | 정해진 차례 | 둘을 함께 끈 값 |

- **결정성 자체**(길 · 덩이 · 함께 도는 요청과 상관없이 같은 비트)는 GeulPU 에서 정수 합의 정확함과 정해진 차례에서 나온다. V1 · V2 ·
  V3 는 모두 결정성을 남긴다.
- 결정성만 끌 수 있는 자리는 어텐션의 두 층 접기다(묶음 경계를 위치로 고정한다). 생성 길의 조각을 기기 · 길이에 맞춰 나누면
  (다른 엔진의 split-KV) 빠를 수 있지만, 길이마다 비트가 달라진다. 이것(V4)은 같은 최적화의 짝을 새로 짜야 해서 V1 ~ V3 를 잰 뒤 정한다.
- 어텐션의 자리 둘(q · k · e · v)은 V1 에 넣지 않는다. 머리 128 의 어텐션 판이 자리 둘로 짜여 있어 따로 짜야 한다. V1 의 값이 크면
  그때 정한다.

### 맞는지 먼저 (재기 전에)
- V1 은 CPU 참조의 자리 하나(`정수계약.행렬곱(…, 자리수=1)`)와 판 시험(판23 꼴 — 선형 판 모두 × 끝손질 × 행)이 다른 칸 0 이어야 잰다.
- V2 · V3 는 CPU 참조와 다르다(정해진 것). 같은 GPU 에서 다섯 길이 서로 같은지(결정성이 남는지)를 본다.
- 정밀도도 적는다: 0.5B 에서 V0 · V1 의 숨은 손실(20단계의 방법 — fp64 참값 대비 KL). 참값을 다시 만들려면 torch 가 든다.

### 재는 것
- CUDA(RTX 4070 Ti — 지금 엔진이 다 자란 길). Vulkan 은 텐서곱을 흉내 내서 값이 섞이므로 쓰지 않는다.
- 7B Q4_0 · Q8_0. `재기_7B` 의 칸(프롬프트 128 · 2048 · 8192, 생성 문맥 0 · 2048 · 8192)과 커널마다(`재기_7B커널` — 행렬곱 · 어텐션 · 그 밖).
- 판은 V0 이 고른 것을 모든 변형에 쓴다(판 고르기의 흔들림을 뺀다).
- V0 과 변형을 번갈아 세 바퀴. 칸마다 세 바퀴의 가운데 값으로 **값 = t(V0) ÷ t(Vk)** 를 셈한다.
- 카드는 비어 있어야 한다(화면은 내장 그래픽). 다른 GPU 일과 함께 재지 않는다.

### 판정 (사용자의 기준 그대로)
칸마다 값을 적고, 생성(가중치를 읽는 시간이 정한다)과 프롬프트(계산이 정한다)를 따로 묶는다.
- **≤ 1.01** — 값이 없다. 그 제약은 같은 최적화에서 공짜다.
- **1.01 ~ 1.2** — 값이 있다. 보이는 이득(정밀도 · 재현성)과 견줘 사용자가 정한다.
- **≥ 1.2** — 사용자의 기준("1.2 ~ 1.3 배는 할 가치가 없다")에 걸린다.
