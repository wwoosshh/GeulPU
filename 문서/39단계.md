# 39단계 — Llama 3.x · Mistral: 세 번째 모델 계열, 구조 llama (사전 등록 2026-10-16)

모델 다양성의 3단계다(1단계는 앱의 'Hugging Face에서 찾기' — 36g, 2단계는 Qwen3 — 37). 지금 엔진이 받는 구조는 qwen2(Qwen2.5 ·
DeepSeek-R1-Distill-Qwen)와 qwen3 다. 로컬에서 가장 많이 쓰는 두 계열 **Llama 3.x** 와 **Mistral** 은 GGUF 에서 같은 구조 이름 `llama` 를
쓰고, 블록은 Qwen2 와 같은 Llama 계열(RMSNorm · RoPE · SwiGLU · GQA · 머리 128)이다. 앱은 지금 이 파일들을 받기 전에 거절한다(36단계).
다른 것은 여섯이다.

1. **RoPE 의 짝** — GGUF 변환기가 머리마다 q · k 무게의 줄을 섞어 두어서(원래 줄 j → 2j, 64 + j → 2j + 1) llama.cpp 는 이웃한 두 칸
   (2i, 2i + 1)을 돌린다(NORM). 원래 모델(Hugging Face)과 Qwen 은 반쪽 (i, i + 64)을 돌린다(NeoX).
2. **RoPE 늘이기** — Llama 3.1 · 3.2 는 `rope_freqs.weight`(F32 64 칸)를 싣는다: 주파수 i 마다 나누는 인자(llama3 늘이기). 파일에서 읽은
   값은 짧은 파장 29 칸이 1, 긴 파장 29 칸이 8(3.1) · 32(3.2), 사이 6 칸이 1.207 … 5.257(3.1) · 1.235 … 9.667(3.2)이다.
3. **eps 1e-5** — RMSNorm 의 eps 가 Qwen(1e-6)과 다르다. 지금 생성기는 eps 를 상수로 둔다.
4. **치우침 없음** — 37단계에서 받았다(없으면 0).
5. **토크나이저** — Llama 3 은 BPE(pre `llama-bpe` — Qwen2 와 거의 같고 숫자를 1 ~ 3 자리로 묶는다)에 BOS 를 붙인다. Mistral 은
   **SentencePiece**(GGUF 의 `llama` — 점수로 합치기 · 바이트 대체 · '▁')로 새로 짓는다.
6. **채팅 틀 · 끝 토큰** — 틀이 셋이고(Llama 3.1 · 3.2 · Mistral v0.3), Llama 3 은 끝 토큰이 여럿이다(`<|eot_id|>` · `<|eom_id|>` · `<|end_of_text|>`).

판정 기준을 결과보다 먼저 적는다.

## 검증의 단위 — 37단계와 같다

비트까지 같다는 것은 판(커널)과 그 짜임의 성질이고 판은 **구조** · **모양** · **형식**에만 달려 있다(37단계). 그래서 이번에도

1. **구조**: 작은 실제 모델(Llama-3.2-3B)과 실제 7 ~ 8B 둘(Llama-3.1-8B · Mistral-7B)로 끝에서 끝, 그리고 계약 · CPU 참조.
2. **모양**: 엔진의 모양 규칙(머리 128 · 질의 폭 = 너비 · 너비는 256 의 배수 · FFN 은 64 의 배수(k-양자화는 256) · 머리 / KV 머리 ≤ 16) 안의
   큰 모양은 **합성 모델**로 비트를 본다 — 이번에는 Llama-3.1-70B 의 모양(층 넷).
3. **형식**: Q8_0 과 Q4_K_M(Q4_K · Q6_K) — 둘 다 엔진이 이미 받는 형식이다.

미세조정 모델(Llama · Mistral 을 바탕으로 한 수많은 GGUF)은 바탕과 구조 · 모양이 같아 따로 볼 것이 없다 — 앱의 받기 전 확인이 파일 머리로
범위를 본다.

## 무엇을 만드나

1. **계약(문서/계약.md 4절에 4.7).** llama 는 (1) **q · k 무게의 줄을 머리마다 되돌린다** — 머리 안의 줄 j < 64 는 파일의 줄 2j, 64 + j 는
   2j + 1(줄을 통째로 옮길 뿐 셈은 없다). 그러면 채널의 차례가 원래 모델(Hugging Face)의 차례가 되고, 그다음은 머리 128 의 RoPE(짝 (i, i + 64))
   · 정수 KV(32 칸 블록)가 **그대로**다. (2) **늘이기 인자** f_i(`rope_freqs` 의 짧은실수, 없으면 1): θ′_i = θ_i / f_i(fp64 나눗셈 — 바르게
   반올림), 각 = 위치 · θ′_i(fp64 곱), cos · sin 은 짧은실수로 바르게. (3) RMSNorm 의 eps 는 모델의 값(1 절 그대로 — 지금 판들의 상수 1e-6 은
   qwen 의 값이었다). 차례를 계약에 적는 까닭: 점수의 32 칸 블록과 KV 의 정수 블록이 채널의 차례에 달려 있어, 차례가 비트를 정한다.
2. **CPU 참조(파이썬 — 대조 도구).** `계약/정수계약.py` 의 `rope표` 에 늘이기 인자, `시험/참조7B.py` 를 llama 로(`llama.*` 열쇠, 줄 되돌리기,
   `rope_freqs`, eps, 출력 묶임 · 따로, BOS).
3. **글 생성기.** eps 를 생성기의 매개로 — llama 모듈 = 머리 128 모듈(치우침은 호스트가 0 으로)에 eps 1e-5. **RoPE 판은 바꾸지 않는다.**
   qwen2 · qwen3 모듈은 이름 · 소스 · PTX · SPIR-V 가 바이트까지 그대로.
4. **글 호스트.** 설정읽기가 llama 를 받는다(`llama.*` 열쇠, eps, `rope_freqs` → RoPE 표, 늘이기를 모르는 다른 열쇠(`rope.scaling.*`)가
   있으면 거절), q · k 무게를 올릴 때 줄 되돌리기(Q8_0 · k-양자화 — 줄마다 따로 양자화되어 있어 줄을 옮겨도 값이 같다), 모듈 이름 · 앱의
   모듈 준비.
5. **글 토크나이저.** Llama 3 의 BPE(pre `llama-bpe` — 숫자 1 ~ 3 자리 · NFC 없음 · BOS), **SentencePiece**(점수로 합치기 · '▁' · 바이트 대체 ·
   BOS), 글 속의 특수 · 제어 토큰 알아보기, 끝 토큰 여럿.
6. **서버.** 채팅 틀 셋(Llama 3.1 · 3.2(날짜 고정) · Mistral v0.3(시스템 말은 첫 사용자 말 앞에)), `/tokenize`(messages) · `/tokenizer_info`
   의 BOS · 끝 토큰, 끝 토큰 여럿에서 멈춤.
7. **앱.** 목록에 다섯 파일(SHA-256 · 라이선스), 받기 전 확인 · 모델 찾기의 구조 llama(모양 규칙 — 1B 처럼 머리 64 는 '실행 안 됨'), 채팅의
   틀 · 끝 토큰, 연구 패널은 그대로.
8. **빠른 점검.** llama 모듈 줄(3B Q8_0 · 8B Q8_0 · 8B K · Mistral Q8_0 · 3B 공유32)과 SASS 넘침 기록.

범위 밖(다음 단계): 질의 폭 ≠ 너비(Qwen3-0.6B · 4B · Mistral NeMo), 머리 64(Llama-3.2-1B), MoE(Mixtral · Qwen3-30B-A3B), 틀의 도구 부르기
(`tools`), Llama 3.2 Vision, 공유32 의 k-양자화.

## 설계

- **q · k 줄 되돌리기 — RoPE 판은 그대로.** 변환기(`convert_hf_to_gguf.py` 의 `permute`)는 머리 하나(128 줄)를 [2][64] 로 보고 두 축을 바꿔
  [64][2] 로 편다 — 원래 줄 h · 64 + j 가 파일의 줄 2j + h 가 된다(k 는 KV 머리마다). 호스트가 무게를 올릴 때 이것을 거꾸로 하면(`가중치.gl` ·
  `가중치K.gl` 의 줄 자리, CPU 참조 `참조7B.py` 의 같은 곳) q · k 는 원래 모델의 채널 차례로 나오고, 지금의 `RoPEKV정수로128`(짝 (i, i + 64)
  · 주파수 i)이 원래 모델의 RoPE(반쪽 돌리기 · 주파수 i)와 같은 셈이 된다. 판을 새로 짓지 않으므로 프롬프트 · 생성 그래프 · 서버 표 · Vulkan ·
  공유32 의 RoPE 가 바이트까지 그대로다. 치우침이 있는 llama 파일(드묾)은 치우침도 같이 되돌린다.
- **늘이기 인자**: `로프.gl` 의 주파수(467 ~ 479)에 θ′_i = θ_i / f_i(fp64 나눗셈 한 번), 나머지 표 짓기(겹배 정밀도 · 경계 검사)는 그대로.
- **eps**: 생성기의 `RMS_eps` 를 명령의 매개로(없으면 지금 값) — 모듈 이름 `llama{Q8|K}_{너비}x{머리}x{KV}x{FFN}x{낱말}` 에 llama 의 eps(1e-5)가
  묶인다. 다른 eps 의 llama 파일은 이번에 받지 않는다(앱이 '실행 안 됨').
- **토크나이저 — Llama 3**: 지금의 바이트 BPE 그대로, pre `llama-bpe` 는 앞자르기에서 숫자를 `\p{N}{1,3}` 으로, **NFC 를 하지 않는다**(Llama 3 의
  토크나이저에는 정규화가 없다). BOS: 채팅 틀은 `<|begin_of_text|>` 를 글로 넣고(특수 토큰으로 알아봄 — BOS 는 하나), 완성의 글 프롬프트 ·
  `/tokenize`(글)는 llama.cpp · vLLM 처럼 BOS 를 앞에 붙인다(`add_special_tokens: false` 면 붙이지 않음). 토큰 번호 프롬프트는 그대로.
- **토크나이저 — SentencePiece(Mistral)**: llama.cpp 의 `llm_tokenizer_spm` 과 같은 규칙 — 공백을 '▁' 로, 글 조각마다 앞에 '▁'(첫 조각과 특수
  토큰 뒤의 조각 — `add_space_prefix`), 글자 단위에서 시작해 **점수가 큰 이웃 쌍부터** 합치고(같으면 왼쪽부터), 어휘에 없는 글자는 바이트 토큰
  `<0xNN>`(종류 6)으로. 되돌리기는 '▁' → 공백, 바이트 토큰 → 바이트, 맨 앞의 공백 하나를 뺀다.
- **끝 토큰 여럿**: 토크나이저가 GGUF 의 eos · eot 와 어휘의 끝 토큰(`<|eot_id|>` · `<|eom_id|>` · `<|end_of_text|>` · `</s>` · `<|im_end|>` ·
  `<|endoftext|>` 가운데 있는 것)을 모아 목록으로. 큰 모델 · 서버는 호스트가 견주므로 판은 그대로(메가판의 두 칸은 작은 모델 그대로).
- **채팅 틀**(서버의 `채팅틀`): 위 '미리 본 것'의 세 꼴을 글로 — Llama 3.1 · 3.2(날짜 고정, `chat_template_kwargs.date_string`), Mistral v0.3
  (시스템은 첫 사용자 말 앞에 `{시스템}\n\n`). 어느 틀인지는 파일의 구조 · pre · 틀 글로 고른다(llama.cpp 처럼). 기본 시스템 말은 없다.

### 미리 짚어 둘 위험

1. **교차검증 스크립트의 덧댐**: `run.ps1` · `runV.ps1` 이 `토크나이저.gl` 의 정확한 줄을 찾는다. 토크나이저를 고치면 그 줄을 지키거나 스크립트도
   함께 고친다 — 친구 PC 의 교차검증(고정한 커밋에서 다시 빌드)이 깨지지 않게, 빠른 점검에 그 덧댐을 시험으로 더한다.
2. **같이 틀리기**: 줄 되돌리기 · 늘이기 인자는 엔진과 CPU 참조를 같은 사람이 짓는다 — 그래서 39a(6)의 독립 대조(llama.cpp)를 판정으로 둔다.
3. **어휘 128,256 의 로짓 판**: 낱말 수가 Qwen(151,936 · 152,064)과 달라 로짓 판 · 상위 k · 서버 표의 크기가 바뀐다(모양 규칙 안 — 합성 모델과
   실제 파일로 본다).
